# Hello everyone
This is a basic overview of Github & its virtual file control. This will be deleted after 1/20 because I do use this account personally.


Anyhow:
All project work occurs in a folder called a __repository__ which often shortened to "repo" in day-to-day language. This repo is stored in the cloud.
In order to actually edit the repo, you must __clone__ it. Cloning is the process of creating a local, ie on your computer, copy of the folder to work on.
In order to sync the changes to local changed files to the local repo, you must __commit__ the changed files to the local repo. Once you feel that the commits you have done are ready to add these changes to the remote repo, you __push__ the commits, which means all the local changes are now in the remote repo.


Sometimes we don't want to have one basic version of the repo. We can create __branches__ which are a copy of the repo at some point in time & function as a clone of the original in the cloud. This branch is edited independently of other branches.
When we don't want to change anything to the original repo, we can __fork__ the repo to work on the repo without effecting others. This is a copy of the original repo & doesn't link back to it like branches.
Sometimes our work in our branches are good to include in the main branch. We can send a __pull request__ to have other collabrators check if your work should be added to the repo with no problems.
__Issues__ are useful as they can track things we want to change in our project, whether it's bugs, performance, etc.
